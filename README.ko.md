## 바로 해 보기: 키, GPU, 계정 없이

[uv](https://docs.astral.sh/uv/)와 디스크가 필요하다. 맥은 약 1.5 GB, 리눅스는 약 6 GB다(PyTorch가 CUDA 라이브러리를 가져온다). 위의 1973년 실제 칩을 노트북에서 돌린다.

```bash
git clone https://github.com/smpark00/seismorescue && cd seismorescue
./setup_env.sh      # 고정 버전 패키지로 Python 3.12 가상환경
./bootstrap.sh      # 함께 받은 체크포인트, 결과, MAT 예시를 out/ 아래에 둔다

# 1. 저장된 SAM 3 경로에 L0와 합의 규칙을 실제로 돌린다. overlay.png, quake.png, provenance.json을 쓴다
.venv/bin/python -I scripts/rescue.py data/real_scans/MAT_73_12_28_0020_LHZ.TIFF --reuse --on 1973-12-28T00:20:00 --off 1973-12-29T00:13:00

# 2. 파일: miniSEED를 쓰고 ObsPy로 다시 읽는다. export.json, quicklook.png
.venv/bin/python -I scripts/export_mseed.py export out/rescue/MAT_73_12_28_0020_LHZ

# 3. 테두리 판독 점수. Spark의 저장된 응답과 관측소 번호표로 낸다
.venv/bin/python -I scripts/l1_context.py replay
.venv/bin/python -I scripts/show_l1.py out/rescue/MAT_73_12_28_0020_LHZ      # 이 칩에서 Spark가 한 일: 요청, 도구 호출, 응답

# 4. 저장된 재추적으로 여는 검토 화면: http://127.0.0.1:8791/ (선을 클릭, A 수락, H 보류, N 다음 구간, Ctrl-C로 끝)
.venv/bin/python -I scripts/review_server.py out/rescue/MAT_73_12_28_0020_LHZ --replay
```

차례로 `accepted 76.1% of trace columns`, `65401 of 86050 s exported`, `'all4': '25/30'`이 나오고, 빨간 **RECORDED RUN** 띠가 있는 화면이 열린다. 결과는 `out/rescue/MAT_73_12_28_0020_LHZ/`에 있다. 화면에서는 18번 줄의 첫 구간을 눌러 보자. 왼쪽에서 오른쪽으로 가는 패스는 위쪽의 큰 진동으로 넘어갔고, 오른쪽에서 왼쪽으로 가는 패스는 줄 위에 남아서 둘이 어긋난다. 저장된 재추적은 잉크 위에 머문다. 24번 줄에서는 저장된 클릭이 줄을 벗어난 역방향 패스 위에 있어서 재추적이 화면 밖으로 나간다. 재추적은 클릭만큼만 좋다. 그래서 사람이 결정한다.

| 단계 | 위 경로에서 | 실제로 돌리려면 ([재현](#재현)) |
|---|---|---|
| L0 기하와 시각, 합의 규칙, miniSEED, 관측소 번호표 | **실제 실행** | 더 필요 없음 |
| Muse Spark 테두리 판독 | 저장본: `results/e4/responses/`, 요청·도구 호출·응답 전부는 `examples/MAT_73_12_28_0020_LHZ/l1/l1_transcript.json` | Meta Model API 키 ([.env.example](.env.example)) |
| Muse Glimmer 테두리 판독 | 저장본: `results/e9/responses/` | llama.cpp, 오픈 웨이트 18 GB, 16 GB GPU |
| SAM 3가 모든 줄을 양방향으로 추적 | 저장본: `paths.npz` | **게이트 접근과 GPU:** `facebook/sam3` 접근 승인을 직접 받아야 한다(기본 가중치를 재배포하지 않는다) |
| 클릭 뒤 SAM 3 재추적 | 저장된 재추적 66개, 녹화라고 표시한다. 스크립트가 검토 창마다 역방향 패스의 경로 위를 한 번씩 클릭했고(73개 중 66개. 나머지 7개는 클릭할 경로가 없거나 줄 끝에 너무 가깝다), 우리는 그중 몇 개만 봤다. 화면은 그 창의 저장된 재추적을 보여 줄 뿐, 내 클릭에 반응하는 것이 아니다 | **게이트 접근과 GPU** 뒤 `--replay`를 뺀다 |

**게이트 접근과 GPU가 필요한 것:** SAM 3 두 행뿐이다. 그 접근이 있으면 [재현](#재현)으로 영상의 전체 데모를 이 저장소에서 돌릴 수 있다. 없으면 위의 녹화 실행을 보게 되고, 그 근거인 로그, 추적, 출력이 [`results/logs/`](results/logs)와 [`examples/`](examples)에 있다.

## 한 문단 요약

1962–1978년 WWSSN(세계 표준 지진 관측망)은 전 세계의 지진을 사진 필름에 기록했다. USGS는 2025년에 이 필름칩 스캔을 CC0로 공개했다. 칩을 다시 데이터로 바꾸는 일은 가장 중요한 곳에서 무너진다. 지진 줄이 이웃 줄을 가로지르며 수백 번 교차하기 때문이다. SeismoRescue는 공개 칩 한 장을 받아 파일을 낸다. 기록 정보(관측소, 시작 시각, 지진과 그 지진이 놓일 줄), 추적기의 두 패스가 맞는 구간만 담은 miniSEED 파형, 나머지를 위한 검토 목록이다. **우리가 미세조정한 Meta SAM 3**가 모든 줄을 양쪽 끝에서 추적하고, 사람이 맞는 획을 클릭하면 그 구간을 다시 추적한다. **Muse Spark**는 필름 테두리에 인쇄된 숫자를 읽고 결정론 도구를 부른다. Meta의 오픈 웨이트 모델 **Muse Glimmer**는 같은 판독을 우리 GPU에서 한다. 그래서 밖으로 보낼 수 없는 스캔도 이 컴퓨터를 떠나지 않는다. 런타임에 호출하는 모델은 모두 Meta 모델이다. 엉킨 지진 줄은 여전히 대부분 사람 일이다. 처음 보는 지진 10개(합성 필름)에서 수락한 지진 줄 열의 94.2%가 줄 간격 ¼ 안이었다. 같은 열에서 평평한 직선은 72.5%다. 실제 필름에서는 중간 규모 지진 두 건에서 수락한 경로가 디지털 기록의 모양을 따라갔다(r +0.91, +0.83). 큰 지진 두 건에서는 그렇지 않았다. 한 건은 거의 수락되지 않았고, 다른 한 건은 수락한 절반이 평평한 직선보다 낫지 않았다. 그 부분은 사람에게 간다.

## 문제

- WWSSN 장주기 칩 한 장에는 약 하루치 지반 운동이 담긴다. 한 줄이 한 시간이고(실제 필름은 3588–3589초), 줄은 약 24개이며, 1분마다 눈금이 찍힌다.
- 조용한 줄은 쉽다. 지진 줄은 어렵다. 큰 지진 두 건(MAT, KIP)에서 흔들림은 줄 간격의 4.8–8.7배라서, 이웃 줄을 거듭 가로지르고 가파른 획은 흐려진다.
- 모든 줄이 똑같이 생겼다. 교차점에서 어느 획이 어느 줄인지는 앞뒤 맥락으로 정해야 한다.

## 하는 일

```mermaid
flowchart LR
  C["공개 필름칩<br/>(CC0 스캔)"] --> L1["L1 맥락 에이전트<br/>Muse Spark 1.3 (API)<br/>또는 Muse Glimmer (로컬)"]
  L1 -->|"테두리에서 ON 시각,<br/>라벨에서 OFF"| L0["L0 기하와 시각<br/>결정론"]
  L0 --> A["L2 정방향 패스<br/>우리가 미세조정한 SAM 3<br/>왼쪽에서 오른쪽"]
  L0 --> B["L2 역방향 패스<br/>같은 SAM 3<br/>오른쪽에서 왼쪽"]
  A --> L3["L3 합의<br/>두 패스가 줄 간격 ¼ 안에<br/>머무는 곳을 수락"]
  B --> L3
  L3 --> L4["L4 사람 검토<br/>클릭 → SAM 3 재추적<br/>수락 또는 보류"]
  L4 --> L6["L6 파일<br/>miniSEED, record.json,<br/>출처 기록, 미리 보기"]
```

| 층 | 하는 일 | 모델 |
|---|---|---|
| **L0** 기하와 시각 | 기록 영역과 극성을 찾고, 줄을 수평으로 맞추고 기준선을 찾는다. 분 눈금으로 초당 픽셀과 줄 주기를 잰다. 선이 시작한 뒤 첫 분 눈금을 ON 시각으로 둔다. 결과: 픽셀마다 UTC 시각. | 없음 (결정론) |
| **L1** 맥락 에이전트 | 인쇄된 테두리 숫자 16개(ON 날짜, ON 시각, 관측소 번호, 성분 코드)와 라벨을 읽는다. 도구 네 개를 부른다. `decode_border`(관측소 번호표), `station_by_code`, `measure_record`(읽은 시각으로 L0 실행), `catalog`(USGS 지진 목록 + TauP → 주 지진이 나타날 줄, ±1). 기록의 숫자는 모두 도구에서 나온다. 라벨에서 읽는 항목(배율, OFF 시각)만 예외다. | **Muse Spark 1.3**; 로컬 판독은 Muse Glimmer |
| **L2** 추적 | 같은 모델로 모든 줄을 두 번 추적한다. 왼쪽 끝에서 정방향으로, 뒤집은 영상에서 오른쪽 끝부터 역방향으로. 두 패스 모두 L0의 기준선에서 출발한다. | **미세조정한 SAM 3** |
| **L3** 합의 | 열마다 판단한다. 두 패스가 줄 간격 ¼(약 9.5 px) 안에 20열 이상 연속으로 있으면 수락하고, 아니면 분쟁이다. 내보내는 값은 정방향 패스다. 규칙은 개발 세트에서 한 번 고른 뒤 고정했다. | 없음 (고정 규칙) |
| **L4** 사람 검토 | 로컬 웹 화면이 분쟁 구간을 확대한다. 사람이 맞는 획을 클릭한다. SAM 3가 그 점부터 다시 추적한다(RTX 5070 Ti에서 약 1초, 노트북의 Apple GPU에서 약 4–5초). 사람이 수락(A)하거나 보류(H)한다. | **SAM 3** (같은 체크포인트, 점 프롬프트) |
| L5 점검 | 물리 점검(줄 이음매, P 피크 대 TauP). | 아직 만들지 않음 |
| **L6** 파일 | 수락한 표본과 사람이 확인한 표본을 L0의 시간 모델에 맞춰 1 Hz로 쓴다. 나머지는 공백이다. | 없음 |

**제품은 파일이다.** 검토 화면은 파일을 만드는 도구다.

| 파일 | 내용 |
|---|---|
| `l1/record.json`, `l1/l1_transcript.json` | 관측소, 성분, ON/OFF, 배율, 주 지진과 예상 줄, 표시, 비용; 요청, 도구 호출, 응답 전부 |
| `overlay.png`, `quake.png` | 전체 기록과 가장 크게 흔들린 줄의 초록/빨강 보기 |
| `paths.npz`, `provenance.json` | 두 패스의 경로; 줄마다 수락 비율과 UTC 검토 구간; 모델과 규칙 해시 |

### Muse Glimmer를 어디에 어떻게 쓰나

- **모델:** `Muse-Glimmer-30B-KQuant-17GB-Q4_K_M.gguf`(16.8 GB)와 비전 프로젝터(1.4 GB), Hugging Face 저장소 `meta-models/Muse-Glimmer-30B-GGUF`. 공개된 가중치를 그대로 쓴다.
- **어디서:** 우리 워크스테이션의 `llama-server`(llama.cpp, CUDA 빌드). 레이어 14.8 GB는 RTX 5070 Ti에, 나머지는 CPU에 둔다. localhost에서만 듣는다. API를 부르지 않는다.
- **하는 일:** L1 판독 단계. Spark와 같은 영상 두 장과 같은 고정 질문을 받는다(칩 전체, 그리고 테두리 숫자와 라벨이 있는 위쪽 35%). 테두리 숫자는 같은 관측소 번호표를 거친다. 설정: 온도 0, 추론 "medium", 최대 4096토큰.
- **결과 (공개 칩 30장, 한 번 실행):** 번호표를 쓰면 칩 24/30이 모두 맞다. Spark는 25/30이다. 칩당 약 2분(중앙값 134초), $0.
- **왜 중요한가:** Spark의 contributor 등급은 Meta가 입력을 학습에 쓸 수 있다. 그래서 공개 CC0 칩만 보낸다. Glimmer는 공유할 수 없는 스캔에도 같은 판독을 해 준다. 지금까지는 공개 칩에서만 돌렸다.
- **이번 버전에서** Glimmer는 한 번의 판독을 맡는다. 여러 턴의 도구 호출 반복은 Spark에서 돈다.

### 시도했지만 안 된 것

- **제로샷 SAM 3.1**(Meta Model API)은 선이 56–212번 닿는 크롭에서 인스턴스를 내지 않는다.
- **교차 판정자로 쓴 Spark**는 34건을 고치고 60건을 망쳤다. **지진학자 에이전트로 쓴 Spark**는 단순 규칙을 넘지 못했다(P 10초 안: 0.67 대 0.71). 그래서 Spark는 읽고 고르며, 재는 일은 도구가 한다.
- 처음 미세조정한 모델은 **SAM 2.1**(tiny, 노트북)이었다. 처음 보는 지진에서 SAM 3가 더 나았고(r 0.848 대 0.802, +0.045 [+0.015, +0.079], 이전 렌더러), 대조 실행으로 이 차이가 학습 길이 때문이 아님을 확인했다. 지금 핵심 모델은 SAM 3다.
- **줄 식별 판정자로 Muse Glimmer 미세조정.** QLoRA 자체는 됐다. Modal H100 한 장에서 4비트, 20스텝, 약 $0.60이었고, 저장한 어댑터를 다시 불러도 로짓이 같았다. 합성 A/B 과제(교차점에서 어느 빨간 경로가 지진 줄에 머무는가)에서 검증 크롭 200장의 정확도가 0.56에서 0.98로 올랐다. 그런데 같은 크롭에서 필름 잉크를 지워도 0.985였다. 모델은 필름이 아니라 빨간 경로의 모양을 배웠다. 이 어댑터는 쓰지 않는다. 잉크 없는 대조군이 잡아냈다.

- **더 작고 덜 엉킨 지진인 ALQ에서는 SAM 3가 평평한 직선을 넘고 장주기 모양을 따라가지만, 진폭 전부를 따라가지는 못한다.** 줄 전체 r +0.75, 수락 구간 +0.91이고, 모델이나 규칙을 만드는 데 쓰지 않은 칩이다. 시각 정렬과 부호는 SAM 3가 아니라 고전 추적기로 이 디지털 기록에 맞췄다. 지진 줄과 옆 줄을 그 맞춤에서 빼도 r +0.76이다. 원형 이동과 위상 뒤섞기는 최대 0.30이고, 지연 탐색의 곁봉우리는 0.47이다. 한계: 칩 한 장, 작은 지진, 진폭 기울기 0.55, 그리고 이 관측소의 다른 칩을 렌더러 보정에 썼다.
- **MAT의 같은 칩에 있는 더 작은 지진(M6.4, 6번 줄)은 수락 표본에서 r +0.83이다**(줄 전체 +0.68, 73% 수락). 이 줄은 실행 뒤에 골랐다. 그 지진이 거기 있기 때문이다. MAT는 개발 칩이다. 그래서 통과 조건을 먼저 적고 깨뜨려 보았고, 버텼다. ±600초 안의 최선 지연은 +1초(r +0.85, ±30초 밖 최대 0.31), 600초 이상 원형 이동 1,500회는 최대 0.19, 위상 뒤섞기 2,000회는 최대 0.23, 다른 줄의 기준은 최대 0.06이다. 600초 창에서 r은 지진 전 −0.27, P파가 도착하는 창 +0.42, 지진 중 +0.94, +0.89다. 18번과 17번 줄도 거의 같은 값이라(+0.83, +0.79) 외톨이 정점이 아니다.
- **SAM 3는 다른 줄로 넘어가 거기 머물 수 있다**(ALQ에서 세 줄). 그때마다 역방향 패스가 동의하지 않았고, 규칙이 거절했다(거의 수락하지 않음). S/2와 0.1 S 칸은 줄마다 오프셋과 추세를 빼므로, 다른 줄에 머문 경로도 점수가 좋게 나올 수 있고, 일부만 넘어가면 맞는 표본이 나빠 보일 수 있다. r은 신호가 있는 줄에서만 도움이 된다. MAT와 KIP에서도 같은 양상을 봤지만 확정하지는 못했다.
- KIP는 로컬 사본이다. 숫자만 공개하고 영상은 공개하지 않는다.

### 7. 시각과 파일

- **참값 없이 잰 L0 시각 (시험):** 같은 자리에 디지털 기록이 있는 1973년 앨버커키(ALQ) 칩을 L0 개발 중에 열지 않고 남겨 두었다(렌더러 보정에는 전에 썼다). 모든 줄의 시각이 3.03초 안이었다(중앙값 −1.6초). 초당 픽셀 오차는 +0.05%이고, 줄 주기는 3588.0초 대비 3588.05초로 나왔다. 개발 칩 MAT에서는 모든 줄이 4초 안이다. (ALQ는 로컬 사본이라 숫자만 적는다.)

- **1973년 디지털 기록과 시각 대조:** 최선 지연 +2초(r 0.53; +1초는 0.52; 1/400–0.08 Hz, 15분 이상 구간 4개, 수락한 선 16.8시간). 두 구간에 신호가 있고(+2초 r 0.74; +1초 r 0.63), 다른 두 구간은 조용해서 정점이 없다. 필름 시계가 1–2초 빠른 것으로 보인다. :59에 정점이 있는 분 눈금 흔적도 같은 쪽을 가리킨다.

이 추적 과제를 벤치마크로 공개한다. 정확한 참값이 있는 합성 필름 영상 285장, NumPy만 있으면 되는 채점기, 평평한 직선을 포함한 우리 기준선이다. 표는 [LEADERBOARD.md](LEADERBOARD.md)에 있고, 참가 방법은 [bench/README.md](bench/README.md)에 있다. 참값이 공개되어 있으니 점수는 신뢰에 기대고, 지금까지 외부 참가자는 없다. 주 분할에서 우리 고전 추적기는 평평한 직선보다 낮다(지진 줄 ¼ 안 23.0% 대 65.8%).

## 한계

- **큰 지진의 엉킨 지진 줄은 여전히 대부분 사람 일이다.** MAT에서는 거의 수락되지 않는다. KIP에서는 절반이 수락되는데, 땅이 거의 움직이지 않은 곳이고 그 구간은 평평한 직선보다 낫지 않다(r −0.22). SAM 3의 지진 줄 r은 0.21(KIP, M7.6)과 0.02(MAT, M7.5)이고, 우연 수준은 약 0.06이다. ALQ의 +0.75는 더 작은 지진 하나(Ms 6.3)이고 진폭이 낮다(기울기 0.55).
- **이 두 지진 줄에서는 우리 오프라인 신경망이 SAM 3보다 나았다.** RA2 r 0.15 대 0.02(MAT), 0.48 대 0.21(KIP), 각자의 디코더 기준이다. ALQ에서는 반대다(+0.50 대 +0.75). 진 것이 아니라 주최 측 규칙 때문에 뺐다.
- **클릭이 모든 것을 고치지는 않는다.** 합성 개발 세트에서 재추적을 모두 무턱대고 수락하면 지진 줄 정밀도가 94.2%에서 87.3%로 떨어진다(평평한 직선 72.7%에서 66.0%). 그 열에서 재추적(48.0%)은 역방향 패스 단독(47.2%)과 비슷하다.
- **지원하는 칩: 한 줄이 한 시간인 WWSSN 장주기 필름.** 약 189,000장인 CC0 아카이브 전체가 아니다. 새 칩 300장에서 L0는 297장 중 167장에서 이 형식을 찾았다.
- **L0 자동 모드는 처음에 ALQ 1975 칩에서 실패했다.** 중간 회색 종이를 음화로 읽었다. 개발 중에 극성 검사를 고쳐서 지금은 이 칩이 무인으로 끝난다. 25줄 모두 나오고 시각은 맞춘 정렬에서 4.0초 안이다(중앙값 −1.4초). 개발 칩의 회귀 점검이지 시험이 아니다. 위의 실제 필름 표는 영역과 극성을 손으로 준 결과다. 새 칩 300장에서 같은 검사는 4장을 음화로 읽었고, 4장 모두 양화였다.
- **경로는 크롭에 달려 있다.** 영역이나 레이아웃이 조금만 달라져도 SAM 3가 다른 줄에서 넘어간다. MAT에서 제품 실행과 평가 틀이 이렇게 다르다. 레이아웃이 달라서 18번 줄이 한쪽에서는 0.0%, 다른 쪽에서는 98.4% 수락이다. 실제 필름 표는 평가 틀을, 맨 위 오버레이는 제품 실행을 쓴다.
- **정밀도는 합성 필름에서 쟀다.** 실제 필름의 정밀도는 모른다. 두 패스는 합성 필름으로 배운 한 모델이라, 합의하면서도 틀릴 수 있다.
- **한 모델의 두 패스는 두 의견이 아니다.** 시작하는 끝은 다르지만 가중치, 학습 데이터, 맹점을 공유한다. 두 번째 신경망을 쓴 이전 규칙이 더 정밀했고, 그 열이 더 쉬웠다.
- **한 번 넘어가면 긴 구간을 잃는다.** 다른 줄로 넘어간 패스는 거기 머무는 경향이 있어서, 넘어간 뒤의 열은 다른 패스가 맞고 땅이 조용해도 분쟁이 된다. MAT의 14번 줄은 정방향 패스가 지진이 올 때까지 기준선에 머무는데도 0.7%만 수락된다.
- **분 표시는 추적하지 않는다.** 어느 패스도 펜의 눈금을 따라가지 않는다. 따로 적지 않으면 표에서 오류로 친다. 내보내기는 그 초를 직선으로 잇는다.
- **큰 흔들림은 목표에 못 미친다.** 진폭 4배부터 지진 줄 정밀도는 분 표시를 빼도 95% 아래다(8배에서 88.4%, 평평한 직선 55.0%).
- **처음 보는 칩에서 L0의 줄 세기는 튼튼하지 않다.** 라벨 근처의 가짜 줄, 24시간이 넘는 기록, 읽지 못한 OFF 시각이 줄 번호를 밀어낸다. 고치기 전까지는 L0 자체 점검이 어긋날 때(새 칩 13장 중 8장, 300장 실행에서 점검할 수 있던 113장 중 78장에서 그랬다) 예상 지진 줄을 불확실하게 본다.
- **30분 줄 칩은 지원하지 않는다.** 공개 장주기 칩 30장의 무작위 표본에서 10장이 이 형식이었다. L0는 이를 표시하고 시각을 내지 않는다. 자동 레이아웃은 그 30장 중 3장과 짝 기록 하나(KON73B)에서 실패했다. 300장 실행에서 L0는 297장 중 72장을 다른 형식으로 표시했다. 그중 일부는 한 줄 한 시간 칩을 잘못 잰 것일 수 있다.
- **ON 눈금 규칙은 기록 세 개에서만 확인했다.** 다른 관측소나 운영자는 1분 다를 수 있다.
- **진폭 단위는 줄 간격이다.** 계기 보정이 없다. 줄마다 중앙값을 빼므로 줄 이음매에 작은 계단이 남는다(중앙값 0.049 S). StationXML은 아직 없다.
- **개발과 시험.** 시험 수치: 자동 수락 표(처음 보는 지진 10개, 한 번 실행), 새 칩 20장의 테두리 판독, 남겨 둔 1973년 ALQ 칩의 L0. 개발 또는 기술용 수치: 규칙 선택, 이전 규칙과의 비교, 클릭 실험, Glimmer 비교, 실제 필름, MAT 시각 점검, 새 칩 300장 실행(한 번 실행, 합격선 없음, 정답 시각 없음). MAT와 KIP는 여러 방법에 썼다. ALQ 1975 장주기 칩은 모델이나 규칙을 만드는 데 쓰지 않았고, 지금은 L0의 개발 칩이라 그 위의 L0 결과는 남겨 둔 결과가 아니다. 다른 ALQ 칩은 렌더러 보정과 라벨 판독 개발에 썼다.
- 클릭 재추적은 오른쪽으로만 가고 줄 끝까지 256열이 있어야 한다. 재추적한 구간을 역방향 패스로 다시 확인하지 않는다.

## 평가 절차

- **녹화 실행의 근거:** [`examples/MAT_73_12_28_0020_LHZ/`](examples/MAT_73_12_28_0020_LHZ)에 `l1/l1_transcript.json`(요청, 도구 호출, 응답 전부), `provenance.json`(모델과 규칙 해시, 줄별 결과), `paths.npz`(두 패스), `review/recorded_retracks.json`(저장된 재추적)이 있다. [`results/logs/`](results/logs)에 실행 로그가 있고, 시험마다 시작 표지(예: [`results/both_directions/holdout7_started.json`](results/both_directions/holdout7_started.json))가 첫 영상 전의 시각과 코드 해시를 남긴다.
- **합성 필름의 정확한 참값:** 렌더러가 줄마다 펜 중심선을 저장한다.
- **지진 단위 분할.** 같은 지진이 학습과 시험에 함께 들어가지 않는다.
- **고정한 뒤 한 번 실행.** 시험은 시작 표지를 쓰고 두 번째 실행을 거부한다. 사전 등록 문구와 코드 해시를 실행 전에 기록한다. 실패도 나온 그대로 적는다. 시험 뒤 `ml_sam3.py`에 가중치가 없을 때의 도움말을, `real_paired_eval.py`에 이름 붙인 상수를 넣어서 표지의 이 두 해시는 지금 파일과 맞지 않는다. 어느 변경도 결과에 영향을 주지 않는다.
- **별도 재계산.** 다른 AI 에이전트가 모델을 돌리지 않고 저장된 경로와 참값에서 지표마다 정의대로 다시 구현했다. 규칙 선택 4,835개, 시험과 이전 홀드아웃 1,552개, 실제 필름 1,142개, 클릭 실험 3,813개 값이 반올림 범위 안에서 모두 맞았고, 부트스트랩도 이 문서의 구간과 0.4포인트 안이었다. 이 README도 파일과 대조해 반올림 실수 다섯 개를 찾았고, 고쳤다. 그 전의 재계산에서 Spark 판독의 칩별 판정 210개가 맞았다. 이번 재계산에서 재추적 자체를 GPU로 다시 돌리지는 않았다.
- **실제 참값.** MAT, KIP, ALQ의 디지털 기록을 WWSSN 장주기 응답으로 바꾼다. 스캔과 시각의 정렬은 고전 추적기로 같은 디지털 기록에 맞췄고, SAM 3가 칩에서 돌기 전에 저장했다. 실제 필름의 우연 |r|은 약 0.06–0.07이다.

## 재현

키 없는 경로는 [맨 위](#바로-해-보기-키-gpu-계정-없이)에 있다. 여기는 실제 실행 경로이고, 거기 표에 적은 것이 필요하다.

```bash
./setup_env.sh && ./bootstrap.sh     # 고정 버전 패키지로 Python 3.12 가상환경 (uv 필요); 함께 받은 체크포인트를 out/ 아래에 둔다

# SAM 3 기본 가중치 (Meta 게이트): https://huggingface.co/facebook/sam3 에서 접근을 요청한 뒤 한 번 받는다
.venv/bin/hf auth login
.venv/bin/hf download facebook/sam3 config.json model.safetensors --revision 3c879f39826c281e95690f02c7821c4de09afae7

# 1. 공개 칩 한 장 끝까지: L1 -> L0 -> L2 -> L3          [GPU; --l1에는 Meta Model API 키]
export MODEL_API_KEY=...             # 환경 변수에서 읽고 출력하지 않는다. .env.example 참고
HF_HUB_OFFLINE=1 .venv/bin/python -I scripts/rescue.py data/real_scans/MAT_73_12_28_0020_LHZ.TIFF --l1
#    --l1 없이는 키가 필요 없다: 라벨 시각을 --on / --off (ISO)로 준다

# 2. 검토 화면, 이 컴퓨터에서만: http://127.0.0.1:8791/    [GPU, 약 2 GB; 키 없음]
HF_HUB_OFFLINE=1 .venv/bin/python -I scripts/review_server.py out/rescue/MAT_73_12_28_0020_LHZ

# 3. 파일: miniSEED + export.json + quicklook.png               [CPU만]
.venv/bin/python -I scripts/export_mseed.py export out/rescue/MAT_73_12_28_0020_LHZ

# 4. Muse Glimmer, 로컬                                          [GPU 16 GB + CPU; 키 없음, 네트워크 없음]
#    먼저 llama.cpp를 CUDA로 빌드하고, meta-models/Muse-Glimmer-30B-GGUF의 GGUF 파일 두 개를 models/muse-glimmer에 받는다
llama.cpp/build/bin/llama-server -m models/muse-glimmer/Muse-Glimmer-30B-KQuant-17GB-Q4_K_M.gguf \
  --mmproj models/muse-glimmer/mmproj-Muse-Glimmer-30B-Q4_K_M.gguf -c 16384 -fit on --jinja -np 1 --port 8792
.venv/bin/python -I scripts/e9_glimmer_labels.py dev     # MAT 칩, 받아 두었다면 ALQ 1975 SHZ 칩도 (data/README.md)
```
